<Step n={1} title="Beyond ASCII">

ASCII has 128 characters: enough for English, not for é, ß, Ж, 日 or 🙂. **Unicode** gives every character in every script its own number, a **code point**, written like `U+00E9` (that's é). There's room for over a million, and about 150,000 are in use.

The first 128 code points are the same as ASCII, so A is still 65: `U+0041` in hex.

</Step>

<Step n={2} title="UTF-8: one to four bytes">

A code point still has to be stored as bytes. **UTF-8**, the encoding almost everything uses now, takes one to four bytes per character: ASCII characters keep their single byte, accented letters take two, most other scripts three, and emoji four. Old ASCII text is already valid UTF-8, which is why it won.

<Step n={3} title="Mojibake">

When a program reads UTF-8 bytes as an older encoding like Windows-1252, every multi-byte character falls apart into two or three wrong ones: é becomes `Ã©`, and a curly apostrophe becomes `â€™`. The Japanese call it **mojibake**, "character transformation".

It's reversible: turn the wrong characters back into their bytes and read them as UTF-8. The inspector offers to do it whenever it sees the telltale pairs.
